## 📌 오늘 학습한 주제

**React 1강 — React 소개 및 세팅**

## 💡 오늘 배운 것

### 1. React는 무엇일까?

**React는 사용자 인터페이스(UI)를 만들기 위한 JavaScript 라이브러리**다. 별도의 프로그래밍 언어가 아니라, JavaScript로 화면을 개발할 때 사용하는 도구다.

HTML·CSS·JavaScript로 화면을 구성하는 기본 원리는 유지하면서, 화면을 **컴포넌트라는 단위로 나누어 개발**한다. [React](https://react.dev/learn/your-first-component)

라이브러리와 프레임워크는 일반적으로 **프로그램의 흐름을 누가 주도하는지**로 구분한다.

| 구분 | 설명 |
| --- | --- |
| **라이브러리** | 필요한 기능을 골라 내 코드에서 활용하는 도구 |
| **프레임워크** | 정해진 구조와 실행 흐름에 맞춰 코드를 작성하는 틀 |

다만 라이브러리도 내부에서 사용자 코드를 호출할 수 있으므로, 호출 방향 하나만으로 모든 차이를 판단하지는 않는다.

### 2. 컴포넌트(Component): 화면을 이루는 부품

React는 **컴포넌트 기반**으로 개발한다. 어릴 때 레고 블록을 조립해 하나의 작품을 만들던 것처럼, **부품(컴포넌트)을 조립해 하나의 웹 화면을 만든다.**

> **컴포넌트 = 화면의 일부를 정의하는, 재사용 가능한 UI 부품**

#### 예시: 숙소 예약 사이트(Airbnb) 화면

숙소 목록 페이지에는 최소 **세 가지 종류의 컴포넌트**가 있다고 볼 수 있다.

| 컴포넌트 | 역할 |
| --- | --- |
| **숙소 카드** | 이미지·지역·거리를 받아 카드 하나를 만들어 냄 |
| **카드/메뉴 영역** | 카드들(또는 카테고리 메뉴)을 묶어서 배치 |
| **페이지** | 위 컴포넌트들을 모두 감싸 하나의 페이지를 완성 |

카드가 화면에 수십 개 보여도 **컴포넌트는 "숙소 카드" 하나**다. 같은 컴포넌트에 **이미지·지역명·거리 같은 데이터만 다르게 전달**해서 서로 다른 카드를 찍어 낸다.

> ⚠️ **주의** 화면만 보고 컴포넌트 개수가 확정되는 것은 아니다. 어떤 단위로 쪼갤지는 **설계하는 사람의 판단**에 따라 달라진다. 위 "3개"는 최소한으로 나눴을 때의 예시다.

### 3. 재사용성과 의존성

컴포넌트 기반 개발의 가장 큰 장점은 **재사용성**이다. 컴포넌트를 잘 만들어 두면, 전달하는 데이터에 따라 원하는 화면 조각을 얼마든지 만들어 쓸 수 있다.

그런데 재사용이 가능하려면 조건이 있다. **다른 모듈에 대한 의존성이 낮아야 한다.**

```
[A 프로그램]                          [B 프로그램]

 CALENDAR 모듈 ──(의존)── DATE 모듈
       │
       └────── 가져다 쓰기 ──────▶  CALENDAR 모듈   ❌ DATE가 없어서 동작 불가

 STRING 모듈 (의존 없음)
       └────── 가져다 쓰기 ──────▶  STRING 모듈     ✅ 독립적이라 바로 재사용 가능
```

| 상황 | 다른 프로그램에서 쓸 때 |
| --- | --- |
| `CALENDAR`가 `DATE`에 **의존** | `DATE`도 함께 가져가거나 대체해야 함 → 재사용 불편 |
| `STRING`이 **독립적** | 그대로 가져가서 사용 가능 → 재사용 쉬움 |

> 💡 의존성을 **완전히 없애라**는 뜻은 아니다. 현실적으로 의존성 없는 코드는 거의 없다. 목표는 **불필요한 의존을 줄이고, 꼭 필요한 의존은 밖에서 전달받도록(props) 명확하게 드러내는 것**이다.

### 4. SPA와 렌더링

**SPA(Single Page Application)** 는 하나의 HTML 문서를 기반으로, 필요한 부분만 갱신하며 동작하는 웹 애플리케이션 방식이다. React는 SPA를 만드는 데 많이 쓰인다.

React로 SPA를 만들 수 있지만, **React 자체가 SPA만을 위한 도구는 아니다.** 기존 페이지의 일부에 적용하거나 다른 렌더링 방식과 함께 사용할 수도 있다.

**렌더링(Rendering)** 은 **화면을 만들어 브라우저에 보여 주는 과정**이다.

- 직접 만든 `login.html`을 브라우저로 열었을 때 화면이 보이는 것 → **렌더링됨**
- `F5`로 새로고침해서 화면이 다시 그려지는 것 → 다시 **렌더링됨**
- 브라우저의 파서가 텍스트(HTML)를 해석(parsing)하고, 그 결과를 화면에 보여 주는 과정 전체를 렌더링이라 부른다.

React에서는 이 과정을 조금 더 나눠 볼 수 있다.

| 단계 | 하는 일 |
| --- | --- |
| **React 렌더링** | 컴포넌트를 호출해 **화면에 무엇을 보여 줄지 계산** |
| **DOM 반영** | 계산 결과 중 **바뀐 부분만** 실제 DOM에 적용 |
| **브라우저 표시** | DOM과 CSS를 바탕으로 **실제로 화면을 그림** |

> 💡 DOM은 브라우저가 HTML 문서를 **객체 구조**로 표현한 것이다. React가 다시 렌더링해도 결과가 이전과 같다면 DOM을 바꾸지 않을 수 있다.

### 5. Component · Props · Element 구분하기

React에서 가장 헷갈리는 세 용어를 **붕어빵**으로 정리해보자.

| 개념 | 의미 | 붕어빵 비유 |
| --- | --- | --- |
| **Component** | 어떤 UI를 만들지 정의한 설계 | 🐟 **붕어빵 틀** |
| **Props** | 컴포넌트에 전달하는 입력 데이터(속성) | 🫘 **속 재료** (팥·슈크림·고구마) |
| **Element** | 컴포넌트가 만들어 내는 결과물 | 🍞 **완성된 붕어빵** |

```
              ┌─────────────┐
 Props(팥) ──▶│             │──▶ Element (팥붕어빵)
 Props(슈크림)▶│  Component  │──▶ Element (슈크림붕어빵)
 Props(고구마)▶│   (붕어빵 틀) │──▶ Element (고구마붕어빵)
              └─────────────┘
```

**같은 틀(Component)이어도 어떤 재료(Props)를 넣느냐에 따라 서로 다른 결과물(Element)이 나온다.** 숙소 카드에서 이미지·지역명·거리가 카드마다 달랐던 것도 바로 Props가 달랐기 때문이다.

> **Props 전달 → Component가 UI 구성 → Element 생성 → 브라우저에 렌더링**
> 
단, React Element는 실제 DOM 요소 자체가 아니다. **React가 화면을 구성할 때 사용하는 UI 설명**이라고 이해하면 된다.

### 6. 함수로 컴포넌트 만들기

React 컴포넌트는 **JavaScript 함수**로 만든다. JavaScript 함수가 "입력 → 출력" 구조인 것처럼, 컴포넌트도 똑같다.

| | 일반 JavaScript 함수 | React 컴포넌트 |
| --- | --- | --- |
| **입력** | 매개변수 | **Props** |
| **출력** | 반환값(아무 값) | **Element** (화면에 그릴 내용) |

```jsx
// 컴포넌트: props를 입력받아 화면에 그릴 내용을 반환하는 함수
function FishBread(props) {
  return <p>{props.filling} 붕어빵</p>;
}

// 컴포넌트를 조합하는 상위 컴포넌트
export default function App() {
  return (
    <div>
      <FishBread filling="팥" />
      <FishBread filling="슈크림" />
      <FishBread filling="고구마" />
    </div>
  );
}
```

| 코드 | 의미 |
| --- | --- |
| `FishBread` | 붕어빵 하나를 표시하는 **컴포넌트(틀)** |
| `filling="팥"` | `filling`이라는 이름으로 **props 전달(재료)** |
| `props.filling` | 전달받은 값을 꺼내 사용 |
| `<FishBread ... />` | 컴포넌트가 만들어 낸 **Element(결과물)** |
| `App` | 여러 컴포넌트를 감싸서 조합하는 **상위 컴포넌트** |

- `<p>...</p>`처럼 HTML과 비슷하게 생긴 문법을 **JSX**라고 한다. JavaScript 안에서 UI 구조를 표현하게 해 준다.
- 컴포넌트는 보통 `.jsx` 파일로 나누어 관리한다.
- 컴포넌트는 **클래스**로도 만들 수 있지만, 현재는 **함수형 컴포넌트가 표준**이다.

> "파일 하나 = 컴포넌트 하나"는 **관례**일 뿐 규칙은 아니다. 한 파일에 여러 컴포넌트를 정의할 수도 있다. 다만 파일당 컴포넌트 하나로 관리하면 찾기 쉽고 재사용하기 좋다.

### 7. Props: 컴포넌트에 전달하는 데이터

**Props**는 **properties(속성)** 에서 나온 이름으로, **부모 컴포넌트가 자식 컴포넌트에 전달하는 데이터**다.

숙소 카드에 전달하는 props 예시는 다음과 같다.

| Props | 전달하는 데이터 |
| --- | --- |
| `image` | 숙소 이미지 |
| `title` | 숙소 이름 |
| `location` | 지역명 |
| `distance` | 거리 |

```jsx
<StayCard image="a.jpg" title="바다 앞 숙소" location="강릉" distance="10km" />
<StayCard image="b.jpg" title="산속 오두막" location="평창" distance="25km" />
```

데이터의 **값은 다르지만, props를 전달하는 형식은 동일**하다. 구조는 재사용하고 **표시할 데이터만 바꾸는 것**이 핵심이다.

- Props에는 문자열뿐 아니라 **숫자 · 배열 · 객체 · 함수**도 전달할 수 있다.
- 전달받은 컴포넌트는 props를 **읽기만 하고 직접 수정하지 않는다.**

## 🔄 흐름 요약

```
React = UI 라이브러리
   ↓
컴포넌트 단위로 화면을 나눠 조립
   ↓
재사용하려면 의존성은 낮게, 필요한 값은 props로 전달
   ↓
[Props] ─▶ [Component(함수)] ─▶ [Element] ─▶ 브라우저에 렌더링
   ↓
함수 컴포넌트 + JSX로 작성
   ↓
Node.js 기반 개발 환경 준비
```
