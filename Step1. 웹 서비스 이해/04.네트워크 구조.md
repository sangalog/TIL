## 📌 오늘 학습한 주제

**웹 서비스 이해 4강 — 네트워크 구조**

브라우저에 보이는 화면을 만드는 **HTML·CSS·JavaScript의 역할**과, **SPA·React·Vue의 관계**를 이해한다.

## 💡 오늘 배운 것

### 1. 프론트엔드(FE) 기술 스택

프론트엔드는 **브라우저를 통해 사용자가 보고 조작하는 화면을 구현하는 영역**이다. 화면의 구조, 디자인, 동작을 함께 만든다.

- 기본 웹 페이지는 `.html` 파일을 중심으로 HTML·CSS·JavaScript를 연결한다. CSS와 JavaScript는 파일 안에 작성하거나 별도 파일로 연결할 수 있다.
- React와 Vue도 이 세 가지 기본 기술을 사용하지만, 화면을 **컴포넌트**로 나누어 만든다.
- **컴포넌트(Component)** 는 버튼·검색창·상품 카드처럼 **화면을 구성하는 재사용 가능한 부품**이다. 상품 카드 하나를 만들고 데이터만 바꿔 여러 상품을 표시할 수 있으며, 여러 컴포넌트를 조합해 하나의 화면을 만든다.
- **React**는 주로 `.jsx` 파일에 컴포넌트를 작성한다. JSX는 JavaScript 안에 HTML과 비슷한 형태로 화면 구조를 작성하는 문법이다.
- **Vue**는 `.js`로도 컴포넌트를 작성할 수 있다. 화면 구조(`<template>`)·로직(`<script>`)·스타일(`<style>`)을 한 파일에 묶는 **단일 파일 컴포넌트**는 `.vue` 확장자를 사용한다.
- Bootstrap은 반응형 화면을 만들 때 활용할 수 있는 CSS 프레임워크다.

> React와 Vue는 단순히 HTML 파일의 확장자만 바꾸는 것이 아니라, 각 기술의 문법과 구조에 맞춰 컴포넌트를 작성한다.

### 2. HTML — 화면의 구조

**HTML(HyperText Markup Language)** 은 웹 페이지에 무엇을 배치할지 정하는 마크업 언어다.

- `<table>`: 데이터를 표로 표현
- `<form>`: 사용자 입력을 받는 양식 구성
- `<header>`, `<article>`, `<footer>`: 각 영역의 의미를 나타내는 시맨틱 태그

브라우저는 태그를 해석해 문서 구조를 만든다. 의미에 맞는 태그를 사용하면 검색 엔진 최적화(SEO)와 접근성에도 도움이 된다.

**HTML과 JSP·ASP의 차이**

- HTML은 브라우저가 해석하는 웹 페이지의 구조를 정의한다.
- JSP는 Java 기반, ASP는 Microsoft 계열의 서버 측 웹 기술이다.
- JSP·ASP는 서버에서 코드를 실행해 HTML 등의 응답을 만들고, 브라우저는 그 결과를 받아 화면을 보여준다.

### 3. CSS — 화면의 디자인

**CSS(Cascading Style Sheets)** 는 HTML로 만든 구조에 색상·글꼴·간격·배치 등을 적용한다.

**반응형 디자인**은 같은 페이지가 PC와 스마트폰처럼 서로 다른 화면 크기에 맞게 배치를 바꾸는 방식이다. PC에서 나란히 보이던 내용을 작은 화면에서는 세로로 배치하는 것이 한 예다.

- **미디어 쿼리**: 화면 너비 등의 조건에 따라 스타일 적용
  - 예: `@media screen and (max-width: 768px)`
- **Flexbox·Grid**: 화면 요소 배치
- **CSS 변수**: 반복해서 쓰는 스타일 값 관리 (`--primary-color`)
- **CSS-in-JS**: JavaScript에서 스타일 작성 (styled-components, emotion 등)

**Bootstrap**은 반응형 그리드와 버튼·입력 폼 같은 UI 구성 요소를 제공한다. 모든 스타일을 처음부터 만들지 않고도 일관된 화면을 구성할 수 있다.

### 4. JavaScript — 화면의 동작

JavaScript는 **사용자의 행동에 반응하고 화면의 내용을 바꾸는 역할**을 한다.

- **이벤트 처리**: 버튼 클릭, 입력 등의 행동에 반응
- **DOM 조작**: 화면 요소나 문구 변경
- **서버 통신**: Fetch API나 Axios 등을 활용해 데이터 요청·반영
- **ECMAScript**: JavaScript의 기반이 되는 언어 표준. `let`, `const`, 화살표 함수, `async/await` 등의 문법과 연결된다.

> HTML은 구조, CSS는 디자인, JavaScript는 동작을 담당한다.

### 5. SPA(Single Page Application)

SPA는 **하나의 문서를 유지하면서 필요한 화면을 바꿔 보여주는 웹 애플리케이션 방식**이다.

화면을 이동할 때 전체 HTML 문서를 매번 다시 받는 대신, JavaScript가 표시할 컴포넌트를 바꾸고 필요한 데이터를 서버에서 받아 화면에 반영한다. 화면 전환마다 서버 요청이 반드시 필요한 것은 아니다.

장점 
1) 전체 페이지를 다시 불러오는 일을 줄여 앱처럼 부드러운 화면 전환이 가능하다
2) 필요한 데이터 위주로 주고받아 전송량과 서버의 페이지 생성 부담을 줄일 수 있다. 

단점
1) 처음 받아 실행할 JavaScript가 많으면 초기 화면 표시가 느려질 수 있다. 
2) 클라이언트 렌더링 중심이면 검색 엔진이 콘텐츠를 파악하기 어려울 수 있다. 

**SSR(Server-Side Rendering)** 은 서버에서 화면의 HTML을 만들어 보내는 방식이다. 초기 화면 표시와 SEO를 보완하는 데 활용할 수 있다. 보안 기능을 뜻하는 것은 아니며, 모든 SPA에 반드시 필요한 것도 아니다.

### 6. React — UI 라이브러리

React는 Facebook에서 시작된 **컴포넌트 기반 UI 라이브러리**다. 버튼·메뉴·목록 같은 화면 부품을 만들고 조합해 재사용한다.

- **JSX**: JavaScript 안에 HTML과 비슷한 마크업을 작성하는 문법 확장이다. HTML 자체와는 문법 차이가 있다.
- **컴포넌트**: 화면에 표시할 내용과 관련 동작을 묶는 단위다. `.jsx` 등에 작성하며, 스타일은 별도 CSS 등으로 연결할 수 있다.
- **Virtual DOM**: UI의 이전·다음 표현을 비교해 실제 DOM 변경을 조정한다. 항상 더 빠르다는 뜻은 아니다.

| 역할 | 예시 |
|---|---|
| 상태 관리 | Redux, Recoil, Zustand |
| 라우팅 | React Router |
| 프로젝트 생성·빌드 | CRA(Create React App), Vite |
| React 기반 프레임워크 | Next.js — SSR 등 지원 |

### 7. Vue.js — UI 프레임워크

Vue는 **HTML과 유사한 템플릿으로 화면을 선언하고, 데이터 변화에 맞춰 UI를 갱신하는 프레임워크**다. HTML·CSS·JavaScript 경험을 바탕으로 접근하기 쉽다.

- **단일 파일 컴포넌트(`.vue`)**: `<template>`에 화면 구조, `<script>`에 로직, `<style>`에 스타일을 작성한다.
- **반응성(Reactivity)**: 데이터가 바뀌면 연결된 화면도 갱신된다.
- **컴포넌트 재사용**: React처럼 화면을 여러 부품으로 나누고 조합한다.

| 역할 | 예시 |
|---|---|
| 라우팅 | Vue Router |
| 상태 관리 | Pinia, Vuex |
| Vue 기반 프레임워크 | Nuxt — SSR·SSG 지원 |

SSG(Static Site Generation)는 빌드할 때 HTML을 미리 생성하는 방식이다.

> React와 Vue는 HTML·CSS·JavaScript를 대체하는 것이 아니라, 이 기술로 화면을 구성하고 관리하는 방식을 제공한다. 둘 다 SPA 구현에 활용할 수 있지만 SPA 전용은 아니다.

### 8. 라이브러리와 프레임워크

둘 다 개발을 돕는 도구지만, **기능을 가져다 쓰는지, 정해진 구조와 흐름 안에서 코드를 작성하는지**에 차이가 있다.

| 구분 | 라이브러리 | 프레임워크 |
|---|---|---|
| 제공하는 것 | 필요한 기능을 수행하는 코드 | 애플리케이션의 구조와 실행 흐름 |
| 기본 관점 | 내가 필요한 기능을 호출한다. | 정해진 흐름이 내가 작성한 코드를 호출한다. |
| 강의 예시 | React | Vue |

프레임워크가 실행 흐름을 맡는 관점을 **제어의 역전(IoC)** 이라고 한다. 다만 실제 도구의 경계는 겹치므로, 호출 방향 하나만으로 모든 도구를 구분하지는 않는다.

## 🔄 흐름 요약

**HTML로 구조 만들기 → CSS로 디자인·반응형 적용 → JavaScript로 동작 구현 → React·Vue로 컴포넌트 구성 → SPA 방식으로 화면 전환**

예를 들어 사용자 목록 화면이라면 HTML로 목록을 구성하고, CSS로 화면 크기에 맞게 배치한다. JavaScript로 사용자 정보를 요청하고, React나 Vue에서는 목록을 컴포넌트로 만들어 데이터 변화에 맞춰 갱신한다.

## ✍️ 내가 이해한 핵심

- 프론트엔드는 **HTML로 구조를 만들고, CSS로 꾸미고, JavaScript로 동작을 구현하는 영역**이다.
- 반응형 디자인은 하나의 페이지가 PC·스마트폰 등 **화면 크기에 맞게 배치를 바꾸는 것**이다.
- React와 Vue는 기본 웹 기술을 활용해 화면을 **재사용 가능한 부품인 컴포넌트**로 나누어 만든다.
- 라이브러리는 필요한 기능을 가져다 쓰는 도구이고, 프레임워크는 **개발 구조와 실행 흐름까지 제공하는 도구**라고 이해했다.
