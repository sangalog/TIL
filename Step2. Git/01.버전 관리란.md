## 📌 오늘 학습한 주제

**Git 1강 - 버전 관리란?**

Git으로 변경 이력을 관리하는 이유를 이해하고, 실습을 위한 기본 설정을 진행했다.

## 💡 오늘 배운 것

### 1. Git이란 무엇인가?

Git이란 **분산형 버전 관리 시스템(Version Control System)** 의 한 종류이며, 빠른 수행 속도에 중점을 둔다.

우리가 레포트를 제출한다고 가정했을 때, 처음에 `report.txt`로 저장했다가 수정을 하면서 `report_final.txt`로 저장하고, 또 수정을 거치면서 `report_final_final.txt`…로 저장한 경험이 있을 것이다.

여기서 이 파일들을 **복사, 백업, 저장 등을 한 것**이고, 이러한 것을 **버전 관리**라고 부른다.

### 2. 버전 관리란?

파일이 **언제, 누구에 의해, 어떻게 바뀌었는지 기록하고 필요한 상태로 되돌리는 것**이다.

- 각 파일을 이전 상태로 되돌릴 수 있다.
- 프로젝트를 통째로 이전 상태로 되돌릴 수 있다.
- 시간에 따른 수정 내용을 비교해 볼 수 있다.
- 누가 언제 어떤 내용을 수정했는지 확인할 수 있다.
- 문제가 발생한 변경 이력을 추적할 수 있다.
- 파일을 잃어버리거나 잘못 고쳤을 때 저장된 이력을 바탕으로 복구할 수 있다.

강사님이 설명한 **시간과 공간 여행**으로 생각하면 이해하기 쉽다.

| 비유 | 의미 |
| --- | --- |
| 시간 여행 | 과거 버전을 확인하거나 변경 내용을 되돌리는 것 |
| 공간 여행 | 브랜치로 작업 흐름을 나누고, 필요한 브랜치로 전환하는 것 |

> 브랜치는 기존 작업과 분리해서 새로운 기능이나 수정 사항을 작업하는 흐름이다.

### 3. Git & GitHub

- **Git**: 내 컴퓨터에서 코드의 변경 이력을 관리하는 도구
- **GitHub**: Git 저장소를 온라인에 올려 공유하고 협업하는 서비스

팀원들이 각자 작업한 코드를 공유하고 합치는 데 활용한다. 혼자 개발할 때도 수정 이력을 남기고 이전 상태로 돌아갈 수 있어 유용하다.

Git을 사용하는 방식은 두 가지로 나눌 수 있다.

| 구분 | 사용 방식 | 예시 |
| --- | --- | --- |
| **CLI**(Command Line Interface) | 터미널에 명령어를 입력 | Git Bash에서 Git 명령어 실행 |
| **GUI**(Graphical User Interface ) | 화면의 버튼과 메뉴를 사용 | SourceTree |

### 4. Git 최초 설정

Git 설치 후 터미널에서 설치 여부와 버전을 확인한다.

```bash
git --version
```

**① 사용자 이름과 이메일 설정**

커밋(변경 내용을 기록한 단위)에 남길 작성자 정보를 설정한다.

```bash
git config --global user.name "이름"
git config --global user.email "이메일"
```

- `--global`: 현재 컴퓨터의 사용자 계정에서 사용하는 Git 저장소에 공통으로 적용한다.
- 이름과 이메일 설정은 **GitHub 로그인과는 별개**다.

**② 설정 확인**

```bash
git config --global user.name
git config --global user.email
```

**③ 기본 브랜치명 변경**

앞으로 새로 만드는 저장소의 기본 브랜치명을 `main`으로 설정한다.

```bash
git config --global init.defaultBranch main
```

> 기존 저장소의 브랜치 이름까지 바뀌는 것은 아니다.
 
## ✍️ 내가 이해한 핵심

- Git은 최종 파일만 보관하는 것이 아니라 **어떻게 수정해 왔는지 이력까지 관리하는 도구**다.
- **Git으로 기록하고, GitHub로 공유한다.** 협업뿐 아니라 혼자 작업할 때도 유용하다.
