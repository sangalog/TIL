## 📌 오늘 학습한 주제

**Git 3강 - Commit 이해하기**

파일의 변경 사항이 커밋으로 남는 과정과 reset·revert의 차이를 이해한다.

## 💡 오늘 배운 것

### 1. SourceTree와 커밋 이력

SourceTree는 **Git의 변경 이력을 화면으로 보여주는 GUI 도구**다. 커밋 메시지, 작성자, 날짜와 파일의 수정 전후 내용을 확인할 수 있다.

**해시값은 각 커밋을 구분하는 식별자**이며, 특정 커밋을 찾아 되돌릴 때 사용한다.

### 2. 변경 사항과 스테이징

Git은 파일 내용의 수정뿐 아니라 **파일의 추가와 삭제도 기록**한다.

| 상태 | 의미 |
| --- | --- |
| Untracked | 아직 Git의 추적 대상에 추가되지 않은 파일 |
| Modified | 추적 중인 파일의 내용이 수정된 상태 |
| Deleted | 추적 중인 파일이 삭제된 상태 |
| Staged | 다음 커밋에 담을 변경 내용이 준비된 상태 |

스테이징은 **여러 변경 사항 중 이번에 기록할 내용을 골라 담는 과정**이다. 특정 파일만 담을 수도 있고 여러 파일의 변경 내용을 함께 담을 수도 있다.

### 3. add와 commit의 차이

- **add**: 변경 내용을 스테이징 영역에 담는다.
- **commit**: 스테이징된 내용을 하나의 버전으로 기록한다.
- **커밋 메시지**: 어떤 변경을 기록했는지 설명하는 글이다.

파일을 저장하거나 add한 것만으로는 커밋 이력이 생기지 않는다. **커밋에는 현재 스테이징된 내용 전체가 들어간다.**

`-am` 옵션은 추적 중인 파일의 수정·삭제를 자동으로 스테이징하고 메시지와 함께 커밋하게 해준다. 다만 **새로운 미추적 파일은 자동으로 포함하지 않으므로 별도로 add해야 한다.**

### 4. 과거로 돌아가는 방법

- **reset**: 브랜치를 원하는 커밋으로 되돌린다. 이후 커밋은 현재 브랜치 이력에서 제외되며, 파일 변경 내용의 유지 여부는 옵션에 따라 달라진다.
- **revert**: 특정 커밋의 변경 내용을 취소하는 새로운 커밋을 만든다. 기존 커밋 이력은 유지된다.

> reset은 이력을 되돌리고, revert는 이력을 남기면서 변경 내용을 취소한다.

## 🔄 흐름 요약

**파일 변경 → 기록할 내용 선택(스테이징) → 버전 기록(커밋) → 이력 확인 → 필요할 때 변경 되돌리기**
