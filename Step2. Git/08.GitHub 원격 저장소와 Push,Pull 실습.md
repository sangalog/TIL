## 📌 오늘 학습한 주제

**Git 8강 - GitHub 원격 저장소와 Push,Pull 실습**

## 💡 오늘 배운 것

### 1. Git과 GitHub의 차이

| 구분 | Git | GitHub |
| --- | --- | --- |
| 의미 | 코드의 버전을 관리하는 프로그램 | Git 저장소를 온라인에 보관하고 협업하는 서비스 |
| 주요 역할 | add, commit, 브랜치 관리 | 코드 공유, Pull Request, 이슈 관리, 자동화 |

**Git으로 내 컴퓨터에서 작업을 기록하고, GitHub로 팀원들과 공유한다.** Git은 GitHub 없이도 사용할 수 있다. GitHub 웹사이트에서 파일을 편집할 수도 있지만, 내 컴퓨터에서 Git 명령어를 쓰려면 Git이 설치되어 있어야 한다.

### 2. 로컬 프로젝트를 GitHub에 올리기

- **로컬 저장소**: 내 컴퓨터에 있는 Git 저장소
- **원격 저장소**: GitHub처럼 원격 서버에 있는 Git 저장소

| 공개 범위 | 의미 |
| --- | --- |
| Public | 누구나 저장소 내용을 볼 수 있음 |
| Private | 권한을 받은 사용자만 접근 가능 |

> **Private 저장소도 팀원을 초대해 협업할 수 있다.** 공개 여부와 다른 사람에게 수정 권한을 주는 것은 별개다.

### 3. 연결된 원격 저장소 확인과 복제

**현재 프로젝트가 어느 원격 저장소와 연결되어 있는지 확인하기**

```bash
git remote -v
```

연결된 원격 저장소의 이름과 주소가 표시된다. **origin은 원격 저장소에 붙이는 이름**이며, 일반적으로 기본 이름으로 사용한다.

**원격 프로젝트를 처음 내 컴퓨터로 가져오기**

```bash
git clone 저장소주소
```

파일뿐 아니라 **커밋 이력 등 Git 관리 정보도 함께 복제**한다. `저장소주소`에는 GitHub에서 복사한 저장소 URL을 넣는다.

### 4. push — 내 커밋을 원격에 올리기

파일을 수정·저장한 뒤, 로컬에 커밋하고 원격에 올린다.

```bash
git add 파일명
git commit -m "변경 내용 설명"
git push -u origin main
```

- `git add`: 커밋할 변경 내용을 준비한다. `파일명`은 실제 수정한 파일명으로 바꾼다.
- `git commit`: 변경 내용을 **내 컴퓨터의 저장소에 기록**한다.
- `git push`: 로컬 커밋을 **원격 저장소에 올린다.**
- `-u`: 로컬 main과 원격 main의 연결 관계를 설정한다.

연결 관계가 설정된 뒤에는 일반적으로 아래처럼 사용할 수 있다.

```bash
git push
```

> **commit만 하면 GitHub에는 반영되지 않는다.** push까지 해야 원격에서도 변경 내용과 커밋을 확인할 수 있다.

### 5. pull — 원격의 변경을 내 컴퓨터에 반영하기

| 구분 | pull 전 | pull 후 |
| --- | --- | --- |
| GitHub | 새 멤버가 추가됨 | 새 멤버가 추가됨 |
| 내 컴퓨터 | 새 멤버가 없음 | **새 멤버가 반영됨** |

```bash
git pull
```

**원격의 새 커밋을 가져와 현재 로컬 브랜치에 통합하는 명령어**다. 단순히 파일을 다운로드하는 것과 달리, 내 작업과 합치는 과정에서 충돌이 발생할 수도 있다.

### 6. 로컬과 원격에서 각각 수정했다면?

같은 파일을 로컬과 원격에서 각각 수정했다고 해 보자.

| 위치 | 수정 내용 | 현재 상태 |
| --- | --- | --- |
| 로컬 | 매니저를 **홍길동**으로 변경 | 커밋 완료, 아직 push하지 않음 |
| 원격(GitHub) | 코치를 **김철수**로 변경 | 원격에서 커밋 완료 |

이 상태에서 `git push`를 하면 **로컬에 원격의 변경 내용이 없어 업로드가 거절된다.**

**① 원격의 변경을 가져와 내 작업과 합치기**

```bash
git pull --no-rebase
```

원격에서 변경한 **코치 ‘김철수’**를 가져와, 로컬에서 변경한 **매니저 ‘홍길동’**과 합친다. 두 변경을 합친 결과는 **새 병합 커밋으로 기록된다.**

> 충돌이 발생하면 내용을 수정하고 저장한 뒤, `git add`와 `git commit`으로 병합을 완료한다.

**② 합친 결과를 원격에 올리기**

```bash
git push
```

이제 로컬과 원격 모두 **매니저는 홍길동, 코치는 김철수**로 반영된다.

> **원격에 내가 받지 않은 커밋이 있다면, 먼저 pull로 가져와 합친 뒤 push한다.**

## 🔄 흐름 요약

**Git·GitHub 구분 → 원격 저장소 연결 → 수정·저장 → add → commit → push**

- 원격 프로젝트를 처음 가져올 때: **clone**
- 이미 연결된 프로젝트의 원격 변경을 반영할 때: **pull**
- 로컬·원격에 각각 새 커밋이 있을 때: **pull로 통합 → 충돌 시 해결 → push**
