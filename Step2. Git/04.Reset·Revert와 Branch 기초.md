## 📌 오늘 학습한 주제

**Git 4강 - Reset·Revert와 Branch 기초**

## 💡 오늘 배운 것

### 1. 커밋 이력 확인하기

`git log`로 지금까지의 커밋과 각 커밋을 구분하는 **해시값**을 확인할 수 있다. 강의에서는 이 해시값으로 되돌릴 대상을 지정했다. 로그 조회 화면이 열리면 `q`로 종료한다.

**해시값은 커밋마다 붙는 고유한 번호표**라고 이해하면 된다. SourceTree에서 확인한 실제 예시는 다음과 같다.

```text
커밋: 81463cb0bec7ab4b5635894f2d7fcb0cfabc9ab8 [81463cb]
```

- `81463cb0bec7ab4b5635894f2d7fcb0cfabc9ab8`: 전체 커밋 해시값
- `81463cb`: 같은 해시값의 앞 7자리를 표시한 축약형

둘은 **같은 커밋**을 가리킨다. 다른 커밋과 구분된다면 명령어에서도 축약형을 사용할 수 있다.

예를 들어 `git show 81463cb`로 해당 커밋의 정보와 변경 내용을 확인할 수 있다. _(해시값 이해를 위한 추가 예시)_

### 2. reset과 revert의 차이

| 구분      | reset                                                 | revert                                     |
| --------- | ----------------------------------------------------- | ------------------------------------------ |
| 의미      | 브랜치를 원하는 커밋으로 되돌림                       | 특정 커밋의 변경을 취소하는 새 커밋을 만듦 |
| 기존 이력 | 돌아간 시점 이후의 커밋이 현재 브랜치 이력에서 제외됨 | 기존 커밋 이력이 유지됨                    |

예를 들어 커밋이 **A → B → C** 순서로 있다면:

- **A로 reset**: 현재 브랜치가 A를 가리키게 된다.
- **B를 revert**: C 뒤에 ‘B의 변경을 취소하는 커밋’이 추가된다. 프로젝트 전체를 B 시점으로 돌리는 것은 아니다.

**첫 번째 커밋으로 돌아갈 때**

```bash
git reset --hard 첫번째커밋의해시값
```

총 5개의 커밋이 있는 상태에서 실행했다.

- 현재 브랜치가 **첫 번째 커밋으로 돌아간다.**
- 실제 파일도 **첫 번째 커밋 당시의 모습으로 바뀐다.**
- 해당 커밋에 있던 파일만 남고, 이후 추가한 파일은 작업 폴더에서 사라진다.

> **`--hard`는 실제 파일까지 해당 커밋의 모습으로 되돌리는 옵션이다.** 아직 커밋하지 않은 수정 내용도 사라질 수 있으므로 주의한다.

**[가격 변경으로 이해하는 revert 예시]**

상품 가격을 수정했다가 취소하는 상황을 생각해 보자.

| 커밋 | 작업 내용                | 파일 상태                 |
| ---- | ------------------------ | ------------------------- |
| A    | 상품 정보 등록           | 가격 10,000원             |
| B    | 가격을 12,000원으로 변경 | 가격 12,000원             |
| C    | 상품 사진 추가           | 가격 12,000원 + 사진 있음 |

여기서 **B를 revert**하면 다음과 같은 새 커밋이 만들어진다.

| 새 커밋 | 작업 내용            | 파일 상태                     |
| ------- | -------------------- | ----------------------------- |
| D       | B의 가격 변경을 취소 | **가격 10,000원 + 사진 있음** |

가격은 다시 10,000원이 되고, C에서 추가한 사진은 그대로 남는다. 이력도 **A → B → C → D**로 이어진다.

> **가격을 올렸던 기록(B)을 지우는 것이 아니라, 가격 변경을 취소한 기록(D)을 추가한다.** 그래서 나중에 “가격을 올렸다가 다시 되돌렸구나”라고 확인할 수 있다.

### 3. 해시값 없이 reset하면?

`git reset --hard`처럼 해시값을 생략하면 **현재 커밋(HEAD)에 저장된 모습으로 파일을 되돌린다.**

예를 들어 가격을 **10,000원으로 커밋한 뒤**, 파일에서 **12,000원으로 수정하고 아직 커밋하지 않은 상황**이라고 해 보자.

```bash
git reset --hard
```

| 구분 | 실행 전 | 실행 후 |
| --- | --- | --- |
| 현재 커밋에 기록된 가격 | 10,000원 | 10,000원 |
| 실제 파일의 가격 | 12,000원 | **10,000원** |

수정한 가격은 사라지고, 현재 커밋에 저장된 가격으로 돌아간다. **`git add`를 했더라도 아직 커밋하지 않았다면 수정 내용이 버려진다.**

**강의에서 사용한 상황**

- **`.git` 백업 복원**: 커밋 기록은 원래대로 돌아왔지만, 실제 파일은 이전 상태로 남아 있었다.
- **`git reset --hard` 실행**: 실제 파일도 복원된 현재 커밋의 모습으로 맞췄다.

> **해시값을 넣으면 지정한 커밋으로, 생략하면 현재 커밋의 모습으로 파일을 맞춘다.** 생략한다고 한 단계 이전 커밋으로 돌아가는 것은 아니다.

### 4. 브랜치는 작업 흐름을 나누는 가지

- 기능 개발이나 테스트처럼 목적에 따라 작업을 나눌 수 있다.
- 각 브랜치에서 작업한 뒤 확정된 내용을 `main` 등에 통합한다.
- 브랜치 생성과 이동은 별개지만, `git switch -c`를 쓰면 한 번에 할 수 있다.

브랜치를 삭제하려면 먼저 다른 브랜치로 이동한다. `-d`는 병합되지 않은 커밋이 있으면 삭제를 막을 수 있고, `-D`는 병합 여부와 관계없이 강제로 삭제한다.

## ⌨️ Git 명령어 정리

### 이력 확인과 변경 되돌리기

| 명령어                            | 역할                                                          |
| --------------------------------- | ------------------------------------------------------------- |
| `git log`                         | 커밋 이력과 해시값 확인                                       |
| `git reset --hard 커밋해시`       | 브랜치와 파일·스테이징 영역을 지정한 커밋 상태로 되돌림       |
| `git reset --hard`                | 파일·스테이징 영역을 현재 커밋인 HEAD 상태로 맞춤             |
| `git revert 커밋해시`             | 지정한 커밋의 변경을 취소하는 새 커밋 생성                    |
| `git revert --no-commit 커밋해시` | 취소할 변경만 반영하고 자동 커밋은 하지 않음                  |
| `git revert --continue`           | 충돌 등을 해결하고 스테이징한 뒤, 중단된 revert를 이어서 진행 |
| `git rm 파일명`                   | 추적 중인 파일을 삭제하고 삭제 내용을 스테이징                |

> `git revert --continue`는 충돌을 해결한 뒤, 중단된 revert 작업을 이어서 진행할 때 사용한다.

> revert의 커밋 메시지 편집기로 Vim이 열리면 `Esc` → `:wq` → `Enter`로 저장하고 종료한다.

### 브랜치 관리

| 명령어                                  | 역할                                         |
| --------------------------------------- | -------------------------------------------- |
| `git branch`                            | 로컬 브랜치 목록 확인                        |
| `git branch 브랜치명`                   | 브랜치 생성                                  |
| `git switch 브랜치명`                   | 해당 브랜치로 이동                           |
| `git switch -c 브랜치명`                | 새 브랜치를 생성하면서 이동                  |
| `git branch -d 브랜치명`                | 병합 여부를 확인하며 브랜치 삭제             |
| `git branch -m 기존브랜치명 새브랜치명` | 브랜치 이름 변경                             |
| `git branch -D 브랜치명`                | 병합되지 않은 커밋이 있어도 브랜치 강제 삭제 |
