## 📌 오늘 학습한 주제

**Git 7강 — 충돌 해결 실습**

## 💡 오늘 배운 것

### 1. 충돌이란?

서로 다른 브랜치에서 **같은 파일의 같은 부분을 다르게 수정해 Git이 자동으로 합치지 못하는 상황**이다.

### 2. VS Code에서 충돌 해결하기

충돌한 파일을 열어 양쪽 내용을 비교하고, 남길 내용을 선택하거나 직접 수정한다.

| 버튼 | 역할 |
| --- | --- |
| Accept Current Change | 현재 내용 선택 |
| Accept Incoming Change | 들어오는 내용 선택 |
| Accept Both Changes | 양쪽 내용 모두 유지 |
| Compare Changes | 두 내용 비교 |

> main에서 다른 브랜치를 merge할 때 Current는 main, Incoming은 합칠 브랜치의 내용이다. rebase에서는 기준이 달라지므로 실제 내용을 확인하고 선택한다.

### 3. merge 충돌 해결하기

main에 conflict01의 작업을 합친다.

```bash
git switch main
git merge conflict01
```

충돌이 발생하면 **남길 내용 선택 → 파일 저장 → add → commit** 순서로 완료한다.

```bash
git add 해결한파일명
git commit
```

> 내용을 선택하고 저장하는 것만으로 끝나는 것이 아니라, commit까지 해야 병합이 완료된다.

### 4. rebase 충돌 해결하기

conflict02에서 작업한 내용을 main의 마지막 커밋 뒤에 이어 붙인다.

```bash
git switch conflict02
git rebase main
```

충돌이 발생하면 **파일을 열어 남길 내용을 정하고 저장**한다.

```bash
git add 파일명
git rebase --continue
```

- `git add`: 충돌을 해결한 파일을 반영할 준비를 한다.
- `git rebase --continue`: 멈춰 있던 rebase를 이어서 진행한다.

**rebase는 커밋을 하나씩 적용하므로 다음 커밋에서도 충돌이 발생할 수 있다.** 그때마다 **수정·저장 → add → rebase --continue**를 반복한다.

**모든 충돌을 해결하고 rebase가 끝나면**, main으로 이동해 작업을 합친다.

```bash
git switch main
git merge conflict02
```

이때 conflict02에는 main의 기존 내용과 충돌을 해결한 작업이 모두 들어 있지만, **main은 아직 기존 커밋을 가리키고 있다.** 따라서 main의 위치를 conflict02의 마지막 커밋까지 앞으로 옮긴다.

> 이렇게 **새 병합 커밋 없이 브랜치 위치만 앞으로 옮기는 방식**을 **Fast-forward**라고 한다.

### 5. 당장 충돌 해결이 어렵다면?

진행 중인 작업에 맞는 명령어로 취소한다.

```bash
git merge --abort    # merge 취소
git rebase --abort   # rebase 취소
```

`--abort`는 잠시 멈추는 것이 아니라 **진행 중인 작업을 취소하고 시작 전 상태로 되돌리는 명령어**다.

### 6. 병합이 끝난 브랜치 정리하기

더 이상 사용하지 않는 브랜치는 main에서 삭제한다.

```bash
git branch -d conflict01
git branch -d conflict02
```

브랜치를 삭제해도 **main에 합쳐진 작업 내용은 남는다.**

## 🔄 흐름 요약

| 상황 | 해결 순서 |
| --- | --- |
| merge 충돌 | 내용 확인 → 수정·저장 → add → commit |
| rebase 충돌 | 내용 확인 → 수정·저장 → add → rebase --continue |
| 당장 해결이 어려울 때 | merge --abort 또는 rebase --abort |
