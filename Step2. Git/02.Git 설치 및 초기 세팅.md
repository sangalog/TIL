**Git 2강 - Git 설치 및 초기 세팅**

## 💡 오늘 배운 것

### 1. Git(Local): 코드 버전 관리

Git은 **내 컴퓨터에서 파일의 변경 이력을 관리하는 도구**다. 인터넷이 없어도 커밋을 남기고 이력을 확인하거나 이전 상태로 돌아갈 수 있다.

| 명령어 | 역할 |
| --- | --- |
| `git init` | Git 저장소 생성 |
| `git status` | 파일의 변경 상태와 스테이징 여부 확인 |
| `git add` | 커밋할 변경 내용을 스테이징 영역에 추가 |
| `git commit` | 스테이징된 내용을 하나의 버전으로 기록 |
| `git log` | 커밋 이력 확인 |
| `git branch` | 브랜치 생성 및 목록 확인 |
| `git merge` | 다른 브랜치의 변경 내용을 현재 브랜치에 병합 |
| `git checkout` | 브랜치나 특정 커밋으로 전환 |

강사님의 **타임캡슐 비유**로 보면 `add`와 `commit`의 차이가 이해하기 쉽다.

- **add**: 타임캡슐에 담을 내용을 고르는 과정 → 커밋 준비
- **commit**: 준비한 타임캡슐을 땅에 심는 과정 → 버전 기록
- **log**: 지금까지 심어 둔 타임캡슐의 기록 확인

> `add`만으로는 커밋 이력이 생기지 않는다. `commit`까지 해야 하나의 버전으로 남는다.


### 2. GitHub(Remote): 코드 공유 및 협업

GitHub는 **Git 저장소를 온라인에 보관하고, 다른 사람과 협업하는 플랫폼**이다. GitHub와 코드를 주고받으려면 인터넷 연결이 필요하다.

| 용어 | 의미 |
| --- | --- |
| Repository(저장소) | 코드와 변경 이력을 보관하는 공간 |
| Fork | 다른 사람의 저장소를 내 GitHub 계정으로 복사 |
| Pull Request(PR) | 내 변경 내용을 검토하고 병합해 달라는 요청 |
| Issue | 버그, 개선 사항, 작업할 내용을 기록하고 논의하는 공간 |
| Actions | 빌드·테스트·배포 등의 작업을 자동화하는 기능 |

- **push**: 로컬의 커밋을 원격 저장소에 올린다.
- **pull**: 원격 저장소의 변경 내용을 가져와 로컬에 반영한다.

> Git은 버전 관리 도구이고, GitHub는 이를 활용한 공유·협업 서비스다. Fork는 온라인 계정으로 복사하는 것이며, 내 컴퓨터로 가져오는 작업은 별도다.

### 3. 첫 커밋 실습

**① 로컬 저장소 만들기**

VS Code에서 `git-demo` 폴더를 열고, 터미널을 Git Bash로 선택한 뒤 실행한다.

```bash
git init
```

숨김 폴더인 `.git`이 생성되며, 이곳에 저장소의 이력과 관리 정보가 보관된다. 이 폴더를 삭제하면 해당 로컬 저장소의 관리 이력도 사라진다.

**② 파일 만들고 상태 확인하기**

실습용 `tigers.yaml`, `lions.yaml` 파일에 팀·매니저·멤버 정보를 작성하고 저장한다.

YAML은 설정이나 데이터를 표현하는 형식이며, 들여쓰기로 구조를 나타내고 `-`로 목록 항목을 표현한다.

```bash
git status
```

새 파일은 처음에 **Untracked(추적되지 않는 파일)** 로 표시된다. 아직 Git의 추적 대상에 추가되지 않은 상태다.

**③ 커밋할 내용 담기**

```bash
# 특정 파일만 추가
git add tigers.yaml

# 현재 폴더와 하위 폴더의 변경 내용을 추가
git add .

# 스테이징 상태 확인
git status
```

`git add .`은 프로젝트 최상위 폴더에서 실행하면 프로젝트 전체의 변경 내용을 담을 수 있다. 단, Git에서 무시하도록 설정된 미추적 파일은 제외된다.

**④ 첫 번째 버전 기록하기**

```bash
git commit -m "첫 커밋"
```

`-m`은 커밋 메시지를 지정하는 옵션이다. 어떤 작업을 기록했는지 알아볼 수 있게 작성한다.

**⑤ 이력 확인하기**

```bash
git log
```

커밋을 구분하는 **해시값**, 작성자, 날짜, 커밋 메시지 등을 확인할 수 있다. 첫 커밋 전에는 조회할 커밋 이력이 없다.

SourceTree에서도 같은 로컬 저장소를 열어 이력을 시각적으로 확인할 수 있다.

## 🔄 흐름 요약

**저장소 생성 → 파일 작성·저장 → 상태 확인 → 스테이징 → 커밋 → 이력 확인**

```bash
git init
# 실습 파일 작성 후 저장
git status
git add .
git commit -m "첫 커밋"
git log
```
