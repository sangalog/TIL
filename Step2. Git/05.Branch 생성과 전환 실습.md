## 📌 오늘 학습한 주제

**Git 5강 - Branch 생성과 전환 실습**

## 💡 오늘 배운 것

### 1. 브랜치는 독립적인 작업 흐름

하나의 프로젝트에서도 운영용, 테스트용, 새로운 기능 개발용처럼 작업을 나눠 진행할 수 있다. 이때 사용하는 것이 **브랜치**다.

- 브랜치를 만들면 생성 시점의 커밋에서 새 작업 흐름이 시작된다.
- 이후 한 브랜치에 커밋해도 다른 브랜치에 자동으로 반영되지는 않는다.
- 나눠 작업한 결과는 나중에 필요한 브랜치로 통합할 수 있다.

### 2. 생성과 이동은 별개

브랜치를 생성했다고 바로 그 브랜치에서 작업하는 것은 아니다. **생성 후 `git switch`로 이동해야 한다.**

브랜치를 이동하면 작업 폴더도 해당 브랜치의 상태로 바뀐다. 삭제할 때는 삭제 대상이 아닌 다른 브랜치로 먼저 이동해야 한다.

### 3. 작업 이력 확인하기

SourceTree에서는 갈라진 브랜치와 커밋 흐름을 그래프로 볼 수 있다. 터미널에서도 `git log`에 옵션을 붙이면 여러 브랜치의 흐름을 함께 확인할 수 있다.

> `git log`는 현재 커밋에서 거슬러 올라갈 수 있는 이력을 보여 준다. 분기 이전의 공통 커밋도 포함된다.

### 4. 브랜치 통합 방식 미리 보기

| 방식 | 내용 |
| --- | --- |
| **merge** | 두 브랜치의 작업 이력을 합친다. 이력이 갈라졌다면 보통 병합 커밋이 만들어진다. |
| **rebase** | 내 브랜치의 커밋을 다른 브랜치의 끝에 다시 적용해 출발점을 옮긴다. |

## 🔄 흐름 요약

**브랜치 생성 → 작업할 브랜치로 이동 → 파일 수정·저장 → add → commit → 브랜치별 이력 확인**

## ⌨️ Git 명령어 정리

| 명령어 | 역할 |
| --- | --- |
| `git branch` | 로컬 브랜치 목록 확인. `*`는 현재 브랜치 |
| `git branch add-coach` | `add-coach` 브랜치 생성 |
| `git switch add-coach` | `add-coach` 브랜치로 이동 |
| `git branch -d add-coach` | `add-coach` 브랜치 삭제 |
| `git add .` | 현재 폴더와 하위 폴더의 변경 내용을 스테이징 |
| `git commit -m "메시지"` | 스테이징한 변경 내용을 메시지와 함께 커밋 |
| `git log` | 현재 커밋 기준 이력 확인 |
| `git log --all --decorate --oneline --graph` | 여러 브랜치의 이력을 간단한 그래프로 확인 |

**로그 옵션 뜻**

- `--all`: 모든 참조가 가리키는 이력 표시
- `--decorate`: 브랜치명, 태그 등의 표시 추가
- `--oneline`: 커밋을 한 줄로 표시
- `--graph`: 분기와 합류를 그래프로 표시

> 파일 수정 후 저장하고 add → commit 순서로 기록한다. 브랜치는 다른 브랜치로 이동한 뒤 삭제하며, 아직 합치지 않은 작업이 있으면 삭제가 제한될 수 있다. 로그 조회 화면은  `q`로  종료한다. 이는 보통 Vim이 아닌 페이저 화면이다.
