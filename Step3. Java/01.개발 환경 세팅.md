## 💡 오늘 배운 것

### 1. 자바는 어디에 쓰일까?

- 대표적인 입문 언어로 **파이썬**과 **자바** 등이 있다. 파이썬은 AI·데이터 분석에, 자바는 웹 백엔드 개발에 활용된다.
- 자바는 국내 **공공기관·금융권의 전산 시스템에 널리 활용되는 언어**이다.
- 웹 서비스에서 자바는 **백엔드**를 맡는다.

| 구분 | 역할 | 기술 |
| --- | --- | --- |
| 프론트엔드(FE) | 사용자의 입력과 화면 상태를 관리하고, 서버에서 받아 온 데이터를 **화면에 렌더링** | React, Vue, HTML/CSS/JS |
| 백엔드(BE) | 요청을 처리하고, 필요하면 **DB나 외부 API에서 데이터를 가져와 응답** | Java + Spring Boot |

- **Java**는 백엔드의 처리 기능을 작성하는 언어이고, **Spring Boot**는 자바로 서버를 개발하기 쉽게 해 주는 프레임워크이다.
- 백엔드뿐 아니라 외부 **오픈 API**와도 통신할 수 있다.
  
### 2. 객체지향은 대상을 ‘정보와 행동’으로 표현하는 것

**OOP(Object-Oriented Programming)** 는 객체의 정보와 행동을 정의하고, 객체들이 서로 협력하도록 프로그램을 만드는 방식이다.

예를 들어 회원을 프로그램으로 표현한다면, 이름·나이 같은 정보와 로그인 같은 행동으로 나눌 수 있다.

| 구분 | 의미 | 회원 예시 |
| --- | --- | --- |
| 변수(variable) | 명사적 특징, 즉 객체의 정보 | 이름, 나이 |
| 메서드(method) | 동사적 특징, 즉 객체의 행동 | 로그인하기, 정보 수정하기 |

변수는 `variable`, 객체의 속성은 `attribute`나 `property`로 표현하기도 한다. 서로 관련된 용어지만 문맥에 따라 의미가 달라질 수 있다.

### 3. 클래스와 인스턴스의 차이

클래스의 `{ }` 블록 안에 변수와 메서드를 정의하고, 이 템플릿으로 프로그램에서 쓸 객체를 만든다.

```java
class 회원 {
    // 변수: 이름, 나이
    // 메서드: 로그인(), 정보수정()
}
```

| 구분 | 의미 | 회원 예시 |
| --- | --- | --- |
| **클래스(class)** | 객체를 만들기 위한 **설계도(템플릿)** | 회원은 이름·나이를 가지고 로그인할 수 있다고 정의 |
| **인스턴스(instance)** | 그 설계도로 만들어 **프로그램에서 실제로 동작하는 객체** | 이름 ‘홍길동’, 나이 20인 회원 / 이름 ‘김철수’, 나이 25인 회원 |

- 같은 클래스로 **여러 인스턴스**를 만들 수 있고, 각 인스턴스가 가진 정보의 값은 같을 수도 다를 수도 있다.

> 클래스와 인스턴스는 같은 것이 아니라, **설계도와 그 설계도로 만든 결과물**의 관계이다.

### 4. JDK·JRE·JVM은 각각 무엇일까?
VS Code는 코드를 작성하는 **편집기**다. 자바 코드를 개발하고 실행하려면 개발 도구와 실행 환경을 제공하는 **JDK**가 필요하다.

| 용어 | 풀네임 | 역할 |
| --- | --- | --- |
| **JDK** | Java Development Kit | 컴파일러·JVM·라이브러리 등 자바 **개발과 실행에 필요한 구성 요소** 제공 |
| **JRE** | Java Runtime Environment | JVM과 라이브러리 등 자바 **실행에 필요한 환경** |
| **JVM** | Java Virtual Machine | 자바 바이트코드를 **실제로 실행하는 가상 머신** |
| **lib** | Library | 프로그램을 만들 때 가져다 쓰는, 미리 구현된 기능 모음 |

**바이트코드**는 자바 소스 코드를 컴파일해 만든, **JVM이 실행할 수 있는 명령어 형식**이다. 보통 `.class` 파일에 저장된다.

- **개발할 때**: JDK의 컴파일러가 자바 코드를 바이트코드로 바꾼다.
- **실행할 때**: JVM이 바이트코드를 실행한다.

> **자바 소스 코드(.java) → 컴파일 → 바이트코드(.class) → JVM에서 실행**

> **JDK는 개발 도구, JRE는 실행 환경, JVM은 실제 실행을 담당한다.** 개념적으로는 **JDK ⊃ JRE ⊃ JVM**의 포함 관계로 이해할 수 있다. JDK를 설치하면 JVM과 라이브러리 등 실행에 필요한 구성 요소도 함께 제공되므로, JRE를 따로 설치할 필요는 없다.

### 5. 운영체제가 달라도 실행할 수 있는 이유
컴퓨터는 CPU, 램, 그래픽 카드 같은 하드웨어로 이루어져 있다. 이러한 하드웨어를 사람이 일일이 직접 제어하기 어렵기 때문에, **운영체제(OS)** 를 설치해 관리하고 그 위에 필요한 소프트웨어를 설치한다. 자바 프로그램은 **OS 위에 설치된 JVM에서 실행**된다.

> ✏️ **구조도**
> ```text
>              App ───────────────────┐
>               │                     │
>   ┌───────────┼───────────┐         │
>   │ JDK       ▼           │         │
>   │      ┌─────────┐      │         │
>   │      │   lib   │      │         │
>   │      └────┬────┘      │         ✕
>   │           ▼           │    OS를 직접 쓰지 않고
>   │      ┌─────────┐      │    JVM을 통해 실행
>   │      │   JVM   │      │         │
>   │      └────┬────┘      │         │
>   └───────────┼───────────┘         │
>               ▼                     │
>   ┌───────────────────────┐         │
>   │          OS           │ ◀───────┘
>   │ Windows·macOS·Linux   │
>   └───────────┬───────────┘
>               ▼
>   ┌───────────────────────┐
>   │    H/W · 하드웨어     │
>   └───────────────────────┘
> ```
> **✕는 자바 프로그램이 JVM을 거치지 않고 OS에서 바로 실행되는 구조가 아니라는 의미다.**<br>
> 실행 구조는 **App → JVM → OS → H/W**


| 용어 | 의미 |
| --- | --- |
| App | 우리가 만든 자바 프로그램 |
| JVM | 프로그램을 실행하는 가상 머신 |
| OS | Windows, macOS, Linux 같은 운영체제 |
| H/W | CPU, 메모리 같은 하드웨어 |

- JVM이 운영체제의 차이를 처리하므로, 자바 프로그램은 **OS에 대한 의존성을 줄일 수 있다.**
- **각 OS에 맞는 호환 JVM이 있으면 같은 바이트코드를 실행할 수 있다.**
- 이를 **“Write Once, Run Anywhere”**(한 번 작성하면 어디서든 실행)라고 표현한다. 단, 자바 버전이나 OS 전용 기능에 따라 제약은 있을 수 있다.
