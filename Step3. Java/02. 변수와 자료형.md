**Java 2강 — 변수와 자료형**

## 💡 오늘 배운 것

### 1. JDK 설치하기

Eclipse Adoptium에서 **Temurin JDK 17**을 운영체제에 맞게 다운로드하고 설치한다. 
- 기본 설치 위치: `C:\Program Files\Eclipse Adoptium\jdk-17.0.20.101-hotspot`
- **bin 폴더**: `java`, `javac` 같은 실행 도구가 들어 있는 곳
- 같은 JDK 17이라도 업데이트·빌드에 따라 폴더명 뒤의 숫자는 다를 수 있다.

### 2. JAVA_HOME과 Path 설정하기

**환경 변수**는 운영체제나 프로그램이 참고하는 설정값이다. JDK의 위치를 알려 주고, 터미널에서 자바 명령어를 찾을 수 있도록 설정한다.

Windows에서 **내 PC → 속성 → 고급 시스템 설정 → 환경 변수**로 이동한다.

| 설정 | 입력할 값 | 필요한 이유 |
| --- | --- | --- |
| **JAVA_HOME** | JDK 설치 폴더 경로 | 개발 도구들이 사용할 JDK의 위치를 찾도록 함 |
| **Path** | `%JAVA_HOME%\bin` 또는 실제 JDK의 bin 경로 | 어느 폴더에서도 `java`, `javac` 명령어를 실행할 수 있도록 함 |

- 시스템 변수에 `JAVA_HOME`을 만들고 JDK 설치 경로를 입력한다. **끝에 `\bin`은 붙이지 않는다.**
- `Path`에 JDK의 bin 경로가 이미 등록되어 있으면 중복으로 추가하지 않는다. 없다면 `%JAVA_HOME%\bin`을 추가한다.
- 변경을 저장한 뒤 **CMD를 새로 열어** 확인한다. VS Code가 열려 있었다면 다시 실행한다.

```bat
java -version
javac -version
```

두 명령어 모두 의도한 **17 버전**이 표시되는지 확인한다. `java`나 `javac`만 입력하면 사용 방법이 나오며, `-version`은 설치 버전을 확인하는 옵션이다.

> **JAVA_HOME은 ‘JDK가 있는 위치’, Path는 ‘명령어를 찾을 위치’** 라고 구분하면 쉽다.

### 3. javac는 컴파일, java는 실행

자바 소스 코드는 사람이 읽고 작성하는 코드다. 이를 JVM이 실행할 수 있는 **바이트코드**로 바꾸는 과정이 컴파일이다.

| 구분 | 역할 | 예시 |
| --- | --- | --- |
| `.java` | 작성한 소스 코드 파일 | `GreetingApp.java` |
| `javac` | 소스 코드를 컴파일 | `javac GreetingApp.java` |
| `.class` | 컴파일 결과인 바이트코드 파일 | `GreetingApp.class` |
| `java` | JVM을 시작해 프로그램 실행 | `java GreetingApp` |

> **소스 코드(.java) → javac로 컴파일 → 바이트코드(.class) → java로 실행**

JVM은 바이트코드를 해석해 실행하며, 자주 실행되는 코드를 기계어로 바꾸는 **JIT 컴파일**도 활용한다. 따라서 자바는 컴파일과 해석 실행을 함께 사용하는 방식으로 이해할 수 있다.

> 바이트코드도 바이너리 형식이다. 구분할 핵심은 **바이트코드는 JVM을 위한 명령어이고, 기계어는 CPU가 직접 실행하는 명령어**라는 점이다.

### 4. 대소문자와 이름 작성 규칙

**자바는 대소문자를 구분한다.** `String`과 `string`, `System`과 `system`은 서로 다른 이름이다.

클래스·변수·메서드 등에 붙이는 이름을 **식별자(identifier)** 라고 한다.

| 대상 | 일반적인 작성 관례 | 예시 |
| --- | --- | --- |
| 클래스 | 각 단어의 첫 글자를 대문자로 작성 | `GreetingApp`, `Teacher` |
| 변수 | 소문자로 시작하고 다음 단어의 첫 글자는 대문자 | `engSum`, `memberAge` |
| 메서드 | 변수와 같은 방식으로 쓰되 행동을 나타냄 | `palying`, `playGround` |

변수·메서드의 `userName` 같은 표기를 **카멜 케이스(camelCase)** 라고 한다.

> 이름의 첫 글자를 대문자·소문자로 정하는 것은 **작성 관례**다. 반면 대소문자를 구분하는 것과 **public 클래스 이름을 파일명에 맞추는 것**은 지켜야 할 규칙이다.

### 5. VS Code에서 첫 프로그램 실행하기

1. `backend` 아래에 `java-project` 폴더를 만들고 VS Code에서 연다.
2. 확장에서 **Extension Pack for Java**를 설치해 자동 완성·오류 확인·실행 기능을 준비한다.
3. `GreetingApp.java` 파일을 만들고 다음 코드를 작성한다.

```java
public class GreetingApp {
    public static void main(String[] args) {
        System.out.println("처음 만나는 자바 세상~~!");
    }
}
```

| 코드 | 의미 |
| --- | --- |
| `public class GreetingApp` | GreetingApp 클래스 정의. 파일명도 `GreetingApp.java`로 작성 |
| `public static void main(String[] args)` | 이 프로그램의 실행이 시작되는 **진입점** |
| `System.out.println(...)` | 괄호 안의 내용을 출력하고 줄바꿈 |

코드를 **저장한 뒤 Run**을 누르면 콘솔에서 아래 결과를 확인할 수 있다.

```text
처음 만나는 자바 세상~~!
```

- Java 확장은 자동 빌드와 오류 확인을 도와준다. **저장 자체가 자바의 컴파일 명령인 것은 아니다.**
- 빨간 밑줄이 나타나면 오류 내용을 확인한다. 특히 `String`, `System`의 대소문자를 점검한다.
- 컴파일 오류가 있으면 정상적인 새 `.class` 파일을 만들 수 없으므로 수정 후 다시 실행한다.

프로젝트는 **Maven·Gradle 같은 빌드 도구**로도 관리할 수 있지만, 기초 문법 학습은 위처럼 간단한 자바 파일로 시작할 수 있다.
