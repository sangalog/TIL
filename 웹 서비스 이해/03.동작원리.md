## 📌 오늘 학습한 주제

**웹 서비스 이해 3강 — 동작 원리**

웹 개발에 필요한 환경과, 프론트엔드·백엔드가 요청과 응답을 주고받는 방식을 이해한다.

## 💡 오늘 배운 것

### 1. 웹 개발 환경

먼저 만들려는 서비스에 맞는 개발 언어와 도구, 서버 환경을 선택한다.

- **개발 언어**: Java, Python 등. Python은 데이터 분석·시각화·통계·인공지능에도 많이 사용한다.
- **IDE(Integrated Development Environment)**: 코드 작성, 실행, 컴파일, 디버깅 등을 돕는 통합 개발 환경이다.
- **서버**: Nginx는 정적 파일 제공이나 요청 전달을, Tomcat은 Java 웹 애플리케이션 실행을 담당한다.

### 2. CRUD

데이터를 다루는 기본 작업 네 가지를 뜻한다.

| 구분 | 의미 |
|---|---|
| Create | 생성·입력 |
| Read | 조회·읽기 |
| Update | 수정 |
| Delete | 삭제 |

프론트엔드에서 백엔드의 기능을 사용하려면 정해진 방식으로 요청해야 한다. 

### 3. HTTP 요청(Request)

**HTTP 메서드는 서버에 어떤 작업을 요청하는지 나타낸다.**

| 메서드 | 대표적인 용도 |
|---|---|
| GET | 데이터 조회 |
| POST | 데이터 생성 |
| PUT | 대상 데이터 전체 교체 |
| PATCH | 데이터 일부 수정 |
| DELETE | 데이터 삭제 |

어떤 주소에 어떤 메서드로 요청하고, 어떤 데이터를 주고받을지는 API 명세서에 정리한다.

### 4. 요청 헤더(Headers)

**헤더는 본문 타입이나 인증 정보 같은 메타정보를 담는다.**

| 헤더 | 의미 |
|---|---|
| Content-Type | 보내는 본문의 형식. 예: `application/json` |
| Authorization | 인증 정보. 예: `Bearer {token}` |
| Accept | 클라이언트가 받을 수 있는 응답 형식 |

예를 들어 `Content-Type: application/json`은 요청 본문이 JSON 형식이라는 뜻이다. **헤더와 바디 모두 서버로 전달되지만, 모든 요청에 바디가 필요한 것은 아니다.**

### 5. 요청 URL 설계(REST 스타일)

URL에는 **어떤 리소스인지**, HTTP 메서드에는 **무엇을 할지**를 표현한다.

- 리소스는 `/users`처럼 명사형 복수로 표현하는 것이 일반적이다.
- `/getUser`처럼 URL에 동작을 넣기보다 `GET /users`처럼 메서드로 구분한다.
- 하위 관계는 `/users/{userId}/posts/{postId}`처럼 나타낸다.
  
### 6. 요청 본문(Request Body)과 JSON

**바디는 서버가 실제로 처리할 데이터를 담는 영역**이다. React나 Vue로 만든 프론트엔드에서도 입력한 정보를 JSON으로 담아 보낼 수 있다.

**JSON(JavaScript Object Notation)** 은 데이터를 주고받는 텍스트 형식이다. 객체는 중괄호 `{ }` 안에 키와 값을 넣고, 키와 문자열 값은 큰따옴표로 감싼다.

```json
{
  "username": "testuser",
  "email": "test@example.com",
  "password": "1234"
}
```

URL은 **요청할 주소**, 헤더는 **요청의 부가 정보**, 바디는 **전달할 데이터**라고 이해했다. 데이터는 JSON 외의 형식으로도 보낼 수 있다.

### 7. HTTP와 HTTPS
- HTTP (HyperText Transfer Protocol)
  - 웹에서 클라이언트 ↔ 서버 간 통신 규칙
  - 요청(Request)과 응답(Response) 구조로 동작
  - 단점: 데이터가 암호화되지 않음 → 도청/변조 위험<br>
  👉 예시: http://example.com<br>
  👉 보안이 필요 없는 단순 테스트, 내부망 서비스에서만 주로 사용

- HTTPS (HyperText Transfer Protocol Secure)
  - HTTP에 **보안(SSL/TLS 암호화)**을 추가한 프로토콜
  - 모든 데이터가 암호화되어 안전하게 전달됨
  - 브라우저에서 자물쇠 🔒 아이콘으로 표시됨<br>
  👉 예시: https://example.com<br>
  👉 금융, 쇼핑몰, 로그인 등 **민감한 정보가 오가는 사이트 필수**

### 8. HTTP 응답(Response)

서버는 요청을 처리한 뒤 **상태 코드, 응답 헤더, 필요한 응답 본문**을 반환한다.

**① 상태 코드: 처리 결과를 알려주는 번호**

| 상태 코드 | 의미 |
|---|---|
| 200 OK | 정상 처리 |
| 201 Created | 생성 완료 |
| 204 No Content | 성공했지만 응답 본문 없음 |
| 400 Bad Request | 잘못된 요청 |
| 401 Unauthorized | 유효한 인증 정보가 없음 |
| 403 Forbidden | 접근이 허용되지 않음 |
| 404 Not Found | 리소스를 찾을 수 없음 |
| 500 Internal Server Error | 서버 내부 오류 |

**② 응답 헤더: 응답에 대한 부가 정보**

- `Content-Type`: 응답 데이터 형식
- `Cache-Control`: 캐싱 정책
- `Set-Cookie`: 클라이언트에 쿠키 설정

**③ 응답 본문: 실제 결과 데이터**

성공 응답 예시:

```json
{
  "status": "success",
  "data": {
    "id": 1,
    "username": "testuser"
  }
}
```

오류 응답 예시:

```json
{
  "status": "error",
  "message": "Invalid email format",
  "code": 400
}
```

본문의 필드 구성은 API마다 다르다. 본문에 적힌 `code`와 HTTP 응답 상태 코드는 별개이므로 명세에 맞춰 사용한다.

### 9. SPA(Single Page Application)

**전체 페이지를 매번 새로 불러오지 않고, 필요한 화면과 데이터를 갱신하는 웹 애플리케이션 방식**이다.

| 기술 | 구분 | 역할 |
|---|---|---|
| React.js | 라이브러리 | 사용자 인터페이스(UI) 구현 |
| Vue.js | 프레임워크 | UI 및 웹 애플리케이션 구현 |

프론트엔드는 서버가 보낸 JSON 데이터를 화면에 반영할 수 있다. JSON은 SPA 전용 형식이 아니며, React와 Vue도 SPA 구현에만 사용하는 것은 아니다.


### 10. API 명세 작성

**API 명세서는 프론트엔드와 백엔드가 어떤 요청과 응답을 주고받을지 정리한 사용 설명서**다. 엔드포인트는 요청 자체가 아니라 **요청을 보내는 주소·경로**다.

명세에는 엔드포인트, 메서드, 설명, 요청 헤더·파라미터·본문, 응답 상태 코드·데이터를 적는다.

| 항목 | 내용 |
|---|---|
| URL | `/users/{id}` |
| Method | `GET` |
| 설명 | 특정 사용자 정보 조회 |
| Request Header | `Authorization: Bearer {token}` |
| Path Variable | `id` (Long, 필수) |
| Response 200 | `{ "id": 1, "username": "testuser", "email": "test@example.com" }` |
| Response 404 | `{ "status": "error", "message": "User not found" }` |

경로 변수는 `/users/1`의 `1`처럼 경로에 들어가고, 쿼리 파라미터는 `/users?page=1`처럼 `?` 뒤에 붙는다.


## 🔄 흐름 요약

**사용자 동작 → 프론트엔드 요청 → 백엔드 처리 → 응답 반환 → 프론트엔드 화면 갱신**

예를 들어 `GET /users/1`로 사용자 정보를 요청하면, 백엔드는 처리 결과에 맞는 상태 코드와 데이터를 돌려준다.

## ✍️ 내가 이해한 핵심

- CRUD는 데이터를 다루는 기본 작업이고, HTTP 메서드는 요청할 작업을 표현한다.
- **URL은 어디로, 메서드는 무엇을, 헤더는 부가 정보를, 바디는 실제 처리할 데이터를 나타낸다.**
- JSON은 데이터를 담는 형식이고, SPA는 화면을 갱신하는 방식이다.
- 프론트엔드와 백엔드는 **API 명세서에 정한 요청·응답 방식**을 기준으로 연결된다.
