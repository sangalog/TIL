## 📌 오늘 학습한 주제

**웹 서비스 이해 2강 — 클라이언트와 서버**

웹 서비스는 **브라우저가 요청하고, 서버가 처리한 결과를 돌려주는 과정**이다. 화면 뒤에서 어떤 일이 일어나는지 순서대로 정리했다.

## 💡 오늘 배운 것

### ① 사용자 요청: 주소를 찾고 서버에 접속한다

브라우저는 서비스를 요청하는 **클라이언트**다. 사용자가 URL을 입력하면 접속할 서버의 주소를 확인하고 요청을 보낸다.

| 용어 | 의미 |
|---|---|
| **URL** | 웹 자원의 위치와 접근 방법을 나타내는 주소. <br>예: `https://example.com/login` |
| **IP 주소** | 네트워크에서 접속할 대상을 찾는 주소. 컴퓨터의 집 주소처럼 생각하면 된다. |
| **도메인** | IP 주소 대신 기억하기 쉽게 사용하는 이름. 예: `example.com` |
| **DNS** | 도메인에 해당하는 IP 주소 등을 찾아주는 체계 |
| **HTTP / HTTPS** | 웹의 통신 규칙 / 통신 내용을 암호화해 보호하는 HTTP |

**도메인은 URL의 일부**이며, **프로토콜은 서로 통신하기 위한 약속**이다.


### ② 서버 처리: 웹 서버 vs WAS

#### 웹 서버와 WAS의 차이

**리소스**는 서버가 제공하는 자원이다. 저장된 파일을 전달하는지, 프로그램을 실행해 결과를 만드는지로 구분하면 이해하기 쉽다.

| 구분 | 웹 서버 | WAS(웹 애플리케이션 서버) |
|---|---|---|
| 주요 역할 | **정적 리소스** (변하지 않는 자원) | **동적 리소스** (프로그램이 처리) |
| 예시 | HTML·CSS·JavaScript 파일, 이미지 전달| Java 기준 JSP, Servlet 등 로그인 검증, 회원 조회, 검색 결과 생성 |
| 제품 | Apache HTTP Server, Nginx | WebLogic(Oracle), WebSphere(IBM), 제우스(티맥스) |
| 비용 | 대부분 **무료** | **고가** |

- 요청은 **웹 서버가 먼저 받고**, 프로그램 처리가 필요하면 **WAS로 넘긴다.**
- **정적 리소스**: 저장된 파일을 그대로 전달한다.
- **동적 처리**: 요청에 따라 프로그램을 실행한다. Java에서는 JSP·Servlet 등을 사용할 수 있다.
  
- WAS에 웹 서버 기능이 있으면 둘 다 처리할 수 있고, 필요하면 웹 서버와 WAS를 나누어 구성한다.

> 운영 구성을 이해하려면 웹 서버와 WAS를 구분해야 한다. 
> <br>상용 WAS에는 비용이 들지만, Tomcat 같은 오픈소스 서블릿 컨테이너도 있다.

#### Spring 내부의 처리 흐름

**Spring은 Java 개발을 지원하는 프레임워크**, **Spring Boot는 Spring의 설정과 실행을 간편하게 해 주는 도구**다. 서버 자체와는 구분해야 한다.

애플리케이션의 역할은 보통 다음처럼 나눈다.

| 계층 | 역할 |
|---|---|
| **Controller** | 요청을 받아 필요한 처리를 연결하고 응답을 구성한다. |
| **Service** | 업무 규칙에 따라 실제 처리 로직을 수행한다. |
| **Repository / Mapper** | DB에서 데이터를 조회하거나 저장한다. |

**요청은 Controller → Service → Repository/Mapper로 전달되고, 결과는 반대 방향으로 돌아온다.**

#### JDBC, ORM, JPA, MyBatis

데이터가 필요하면 애플리케이션이 DB에 접근한다. 이때 사용하는 기술들은 같은 역할의 이름이 아니라, 각각 맡는 범위가 다르다.

| 용어 | 의미 |
|---|---|
| **JDBC** | Java에서 DB에 연결하고 SQL을 실행하기 위한 표준 API |
| **ORM** | Java 객체와 관계형 DB를 연결하는 기술. 클래스와 테이블, 필드와 컬럼 등을 매핑한다. |
| **JPA** | Java의 ORM 표준 명세. Hibernate 같은 구현체가 SQL 생성·실행 등을 담당한다. |
| **MyBatis** | 직접 작성한 SQL을 실행하고 결과를 Java 객체와 연결하는 SQL 매퍼 |

**JPA는 객체 중심, MyBatis는 직접 작성한 SQL 중심**으로 생각하면 된다. 둘 다 DB 접근을 돕지만, MyBatis를 JPA와 같은 ORM으로 보지는 않는다.

### ③ 데이터베이스(DB) 처리

프로그램에 필요한 회원·게시글·상품 정보를 저장하고, 요청에 따라 조회·추가·수정·삭제한다.

| 구분 | 의미 | 예시 |
|---|---|---|
| **DB** | 체계적으로 저장된 데이터의 집합 | 회원 정보, 상품 정보 |
| **DBMS** | DB를 관리하는 소프트웨어 | Oracle Database, SQL Server, Db2 |
| **RDBMS** | 테이블과 관계를 기반으로 데이터를 관리하는 DBMS | MySQL, PostgreSQL, Oracle Database |
| **NoSQL** | 문서·키·값 등 관계형 테이블과 다른 모델을 사용하는 DBMS 계열 | MongoDB, Redis, Cassandra |

- **SQL(Structured Query Language)** 은 관계형 DB에서 데이터를 조회하거나 변경할 때 사용하는 언어다.
- **벤더**는 제품을 제공하는 업체다. 대표적으로 Oracle, Microsoft, IBM 등이 있다.
- 오픈소스 제품과 상용 제품이 있으며, **오픈소스에도 유료 지원이 있을 수 있다.** 기업에서도 오픈소스 DBMS를 사용한다.
- NoSQL도 데이터를 조회하는 방법이 있다. **‘SQL이 전혀 없다’고 단정하기보다는 데이터 모델이 다르다고 이해한다.**

### ④ 클라이언트 처리: 응답을 화면으로 보여준다

브라우저는 서버의 응답을 받고 필요한 자원을 처리해 화면을 만든다.

- **HTML**: 화면의 구조와 내용
- **CSS**: 색상·글꼴·배치 등 스타일
- **JavaScript**: 사용자 동작 처리와 화면 갱신
- **렌더링**: 처리한 내용을 실제 화면에 그려내는 과정

응답이 JSON 데이터라면 JavaScript 등으로 화면에 반영할 수 있다. 이후 사용자가 버튼을 누르거나 검색하면 요청과 응답이 다시 반복된다.

## 🔄 흐름 요약

URL 입력 → DNS로 IP 확인 → HTTP/HTTPS 요청<br>
→ 웹 서버 → WAS에서 애플리케이션 처리 → 필요하면 DB 접근<br>
→ 서버 응답 → 브라우저가 화면에 표시

> 웹 서버와 WAS를 분리한 구성의 예시다. **정적 파일은 웹 서버에서 바로 응답할 수 있고, 모든 요청이 DB까지 가는 것은 아니다.**

## ✨ 내가 이해한 핵심

**브라우저는 요청하고 보여주는 역할, 서버는 처리하는 역할, DB는 데이터를 보관하는 역할이다.** 지금은 각 기술을 모두 외우기보다, 전체 흐름에서 어디에 쓰이는지 연결해서 이해하는 것이 중요하다.
